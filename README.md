# Learning Management API

REST API для управления учебным процессом: преподавателями, курсами, студентами, учебными группами и расписанием занятий.

## Возможности

- создание, получение, изменение и мягкое удаление преподавателей;
- создание, получение, изменение и мягкое удаление курсов;
- создание, получение, изменение и мягкое удаление студентов;
- создание, получение, изменение и мягкое удаление учебных групп;
- запись учебной группы на курс и снятие группы с курса;
- добавление студентов в одну или несколько учебных групп;
- создание и изменение расписания занятий;
- просмотр расписания с фильтрами по группе, курсу и преподавателю;
- пагинация и фильтрация списков;
- автоматическое мягкое удаление занятий, завершившихся более года назад;
- документация API через Swagger UI.

## Технологии

- Java 21;
- Spring Boot;
- Spring Web MVC;
- Spring Data JPA;
- PostgreSQL;
- Liquibase;
- MapStruct;
- Bean Validation;
- SpringDoc OpenAPI;
- Docker и Docker Compose.

## Модель данных

- Один преподаватель может вести несколько курсов.
- Каждый курс ведёт один преподаватель.
- Студент состоит минимум в одной учебной группе.
- Студенты и учебные группы связаны отношением «многие ко многим».
- Учебные группы и курсы также связаны отношением «многие ко многим».
- Занятие связывает учебную группу, курс и преподавателя курса.
- Удаление сущностей выполняется мягко: в БД заполняется поле `deleted_at`, а удалённая запись перестаёт быть доступной через API.

## Запуск через Docker Compose

Для запуска нужен установленный Docker Desktop.

```bash
docker compose up --build
```

Команда:

1. собирает Spring Boot-приложение в Docker-образе;
2. запускает PostgreSQL;
3. ожидает готовности PostgreSQL;
4. запускает приложение и применяет миграции Liquibase.

После запуска приложение доступно по адресу:

```text
http://localhost:8080
```

Swagger UI:

```text
http://localhost:8080/swagger-ui.html
```

PostgreSQL доступен с хоста по адресу:

```text
host: 127.0.0.1
port: 5433
database: learning-management
username: postgres2
```

Для остановки контейнеров:

```bash
docker compose down
```

Эта команда сохраняет данные PostgreSQL в Docker volume `postgres_data`.

> Для полного удаления контейнеров и данных БД можно использовать `docker compose down -v`. Это удалит все данные учебного проекта из Docker volume.

## Основные точки API

| Метод | URL | Назначение |
|---|---|---|
| `GET`, `POST` | `/teachers` | Работа с преподавателями |
| `GET`, `PUT`, `DELETE` | `/teachers/{id}` | Работа с одним преподавателем |
| `GET`, `POST` | `/courses` | Работа с курсами |
| `GET`, `PUT`, `DELETE` | `/courses/{id}` | Работа с одним курсом |
| `GET`, `POST` | `/students` | Работа со студентами |
| `GET`, `PUT`, `DELETE` | `/students/{id}` | Работа с одним студентом |
| `GET`, `POST` | `/study_groups` | Работа с учебными группами |
| `GET`, `PUT`, `DELETE` | `/study_groups/{id}` | Работа с одной группой |
| `PUT`, `DELETE` | `/study_groups/{groupId}/courses/{courseId}` | Запись группы на курс и снятие с курса |
| `GET` | `/study_groups/{groupId}/courses` | Курсы конкретной группы |
| `GET`, `POST` | `/schedules` | Просмотр и создание занятий |
| `GET`, `PUT`, `DELETE` | `/schedules/{id}` | Работа с одним занятием |

Подробные запросы, параметры, тела запросов и возможные HTTP-статусы приведены в Swagger UI.

## Пагинация и фильтрация

Для постраничного получения сущностей используются параметры:

```text
page — номер страницы, начиная с 0
size — размер страницы
sort — поле сортировки
```

Например:

```text
GET /teachers?page=0&size=10
GET /courses?name=Java&teacherId=4&page=0&size=10
GET /schedules?groupId=1&teacherId=4&page=0&size=10
```

## Фоновая задача

Каждый день в `03:00 UTC` приложение проверяет занятия. Если занятие завершилось более года назад, оно мягко удаляется: поле `deleted_at` заполняется текущим временем, и занятие исчезает из активных результатов API.
